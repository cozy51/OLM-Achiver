# Outlook Mail PDF Archiver for Edge

Outlook on the web で現在開いているメールを PDF 化する Microsoft Edge 拡張機能です。PDF の先頭には元メールを開くクリック可能な URL を挿入します。

アイコンはOutlookを連想できる青系の配色と`O`を残しつつ、白い書類と`PDF`バッジを組み合わせた本拡張機能専用のデザインです。PNGは`icons/`に同梱済みなので、生成の操作は不要です。

## インストール

1. Edge で `edge://extensions` を開きます。
2. **開発者モード**をオンにします。
3. **展開して読み込み**を選び、このフォルダーを指定します。事前のビルド操作は不要です。

`edge://extensions`のカードにもツールバーにも、同梱の専用アイコンが表示されます。

デザインを変更するときだけ`python3 scripts/generate_icons.py`を実行し、更新された`icons/*.png`をコミットしてください。

すでに Outlook を開いている場合も、そのまま利用できます。

## 使い方

1. Outlook on the web で保存したいメールを1通開きます。
2. ツールバーの拡張機能アイコンを押し、**📩 このメールを PDF 保存**を選びます。
3. 保存先を選択します。

組織のセキュリティ設定により Edge のPDF機能へ直接接続できない場合は、自動的に標準の印刷画面へ切り替わります。印刷画面の「プリンター」で **PDFとして保存** を選択してください。

ファイル名は `📩_差出人_年月日_日時_件名.pdf` です。添付ファイルがあるメールは先頭が `📩📎_` になり、フォルダーの一覧でPDFを開かずに見分けられます。目印は一覧に載せた内容と一致します。添付欄を読み取れなかったメールには付かず、そのことは保存時に拡張機能の画面へ表示します。項目の区切りは `_` なので、ファイル名に使えない文字(`\ / : * ? " < > |`)は `-` へ置き換えます。`Ito Takeshi / 伊藤剛` は `Ito Takeshi - 伊藤剛` となり、区切りと見分けがつきます。件名先頭の `RE:`、`FW:`、`FWD:`、`返信:`、`転送:`（重複を含む）は自動的に取り除きます。重要度記号付きの`[!]RE:`や、すでに区切りが置換された`[!]RE_`も削除します。

`年月日_日時`にはPDFを作成した時刻ではなく、Outlookのメールヘッダーに表示される受信日時（例: `2026-07-13 (月) 20:41`）を使用します。

> PDF 作成中に Edge の「デバッガーがこのブラウザーに接続しました」という通知が一時的に表示されます。これは印刷 API を利用するための正常な動作です。

## 添付ファイル

添付ファイルがあるメールでは、件名の下に`添付ファイル (2件)`の一覧を差し込みます。保存後は拡張機能の画面にも`添付ファイル 2件の名前とリンクをPDFに記載しました: ...`と表示します。

- OneDrive・SharePoint 上のファイル(クラウド添付)は、そのファイル自身のURLへリンクします。リンク先は文字としても書き出します(紙に印刷するとリンクは失われるため)。
- メールに埋め込まれたファイルはURLを持たないため、ファイル名だけを記載します。ページ先頭のリンクが既にそのメールを開くので、同じリンクを行ごとに繰り返しません。

添付ファイルの一覧は、Outlookが添付欄に付けるID・ラベル(`MSG_<item>_ATTACHMENTS`、`添付ファイル`／`画像添付ファイル`)から探します。**探す範囲は閲覧ウィンドウの中だけです。** 左のメール一覧の行にも`添付ファイルあり`というラベルが付くため、ページ全体を対象にすると、開いているメールの添付として一覧の他メールの添付が並んでしまいます(実際に、添付のないメールのPDFへ一覧の6行分が載りました)。閲覧ウィンドウの外に添付欄を描くビルドに備えてページ全体も探しますが、そのときは`MSG_<item>_ATTACHMENTS`のように**それ自身が添付欄だと名乗るもの**に限り、メール一覧の行(`role="option"`)の中にあるものは採用しません。

1件の添付は1つの`role="option"`として描かれ、その読み上げラベルは`Image (1).jpg 開く 6 MB`のように「ファイル名・操作・サイズ」を空白でつないだ文字列です。区切り文字が当てにならないため、**拡張子を境目**として扱います。拡張子より前がファイル名、後ろはタイルの説明です。`Image (1).jpg`のように名前自体が空白と括弧を含むため、単語に分割せず拡張子の位置から切り出します。

メールに添付されたメール(`Outlook アイテム`)は拡張子を持たず、名前の位置に件名が入ります。実機のラベルは`【79584】FST PBN CST LP & CST見学報告 開く 250 KB`のように、種別(`Outlook アイテム`)はタイルの脇に描かれてラベルには入りません。そのため、拡張子がない場合は`開く`のような操作名を境目として、その手前を名前として採用します。

拡張子も操作名もない場合は、ラベル全体を名前として採用します。ただしこれは**添付欄の中のタイル(`role="option"`など)自身のラベル**に限ります。タイルの外にある文言(`添付ファイル 2 個`の合計行、`すべてダウンロード`のボタン)は、どれだけ名前らしく読めても採用しません。拡張子という証拠がない名前を認めてよいかどうかは、それがタイルのラベルであるかどうかで決まります。タイル内のボタンのラベルも、タイル自身のラベルを優先することで除外します。

この判定により、`添付ファイル 2 個 (6 MB)`のような合計行、`すべてダウンロード`のようなボタン、`1.5 MB`のようなサイズは一覧に入りません(拡張子には英字が必要なので`.5`は拡張子と見なしません)。数え上げは名前ではなくタイル単位です。1つのタイルの中でラベルとプレビュー画像が同じ名前を持っていても1件と数え、逆に同名のファイルが2つ添付されていれば2件として並べます。

添付欄の構造が変わって読み取れない場合でも、PDFの保存自体は従来どおり続行します(一覧が省かれるだけです)。このとき拡張機能の画面には`添付欄は見つかりましたが、ファイル名を読み取れませんでした`と表示します。添付ファイルのないメールでは何も表示しません。「添付ファイルがないメール」と「読み取れなかったメール」を、同じ無表示で済ませないためです。

### 添付ファイルが一覧に出ないときの調査

画像添付はサムネイルだけが表示され、ファイル名が画面に出ません。名前がDOMのどこにあるか(`aria-label`・`alt`・`aria-labelledby`の参照先など)はOutlookのビルドによって異なるため、`tools/inspect-attachments.js`で実際の構造を確認します(拡張機能の一部ではありません)。

1. 添付ファイル付きのメールを開き、`F12`で DevTools を開いて`コンソール`タブを選びます。
2. 貼り付けが禁止されている場合は、コンソールに`allow pasting`と入力して Enter を押します。
3. `tools/inspect-attachments.js`の全体を貼り付けて Enter を押します。結果はクリップボードにコピーされます。

出力は構造だけです。ファイル名は`***.jpg`のように拡張子と文字数の形だけを残して伏せます。拡張子は判定に使っている手がかりそのものなので残し、氏名・メールアドレス・本文は伏せます。この結果があれば、その環境のOutlookに合わせて収集元を追加できます。

### 添付でないものが一覧に出るときの調査

逆に、添付ファイルでないものが一覧に並ぶ場合は`tools/inspect-detected-attachments.js`を同じ手順で貼り付けます。こちらは拡張機能と同じ収集・判定をその場で走らせ、**検出した名前ごとに、どの要素のどのラベルから、どの判定経路で採用されたか**を出力します。余分な1件がどこから来たのかが分かります。

検出した名前はPDFに載る文字列そのものなので伏せません。それ以外のラベルは同じ規則で伏せます(メールアドレスは`<MAIL>`になります)。

実行する画面によって結果が変わります。拡張機能は保存を押したその瞬間の画面を読むため、**PDFを保存したときと同じ画面**(通常のOutlook画面で対象メールを閲覧ウィンドウに開いた状態)で実行します。PDF内のリンクから開いた単独表示の画面は作りが違い、添付欄が0か所になることがあります。添付欄が見つからない画面でも、先頭の`SUSPECT`にPDFへ出た余分な名前を入れておけば、その文字列がタイルのラベルにあるのか引用された本文にあるのかを追跡できます。

たとえば`yasuhiro.nishi@akl.muratec.co.jp`のようなメールアドレスは、末尾が拡張子の形をしているため`yasuhiro.nishi`というファイル名として読み取られていました。アドレスが占める範囲を先に求め、その中の拡張子は採用しません。アドレスだけのラベルは、どの判定経路でも名前になりません。

## 利用マニュアル

配布用のマニュアルは`docs/manual.html`です。PDFは次のコマンドで生成します(Chromium系ブラウザーと日本語フォントが必要です)。生成物`docs/*.pdf`はリポジトリに含めません。


## 対応 URL

- `outlook.office.com`
- `outlook.office365.com`
- `outlook.cloud.microsoft`

Outlook の画面構造が変更された場合は、メール本文を検出できなくなる可能性があります。

差出人は拡張機能を開いた時点で自動検出し、`差出人名`欄へ入力します。画面に出るのは確定した1件だけで、次点以下は表示しません。

- 検出には3系統の手がかりを使います。(1) Outlookが差出人欄そのものに付けるID・属性(`MSG_<item>_FROM`、`data-testid`など)、(2) 選択中のメール一覧行の読み上げラベル(先頭が差出人)、(3) 宛先ブロック(`data-testid="RecipientWell"`、`MSG_<item>_TO`)より上のヘッダー領域。
- 順位付けには次点以下も使います。複数の手がかりが同じ人物を指すことが、自動入力してよいかどうかの判断材料になるためです。手がかりが弱い場合も欄には入力しますが、`念のため確認してください`と表示します。
- 最終的な値は常に`差出人名`欄の内容です。誤りは直接修正でき、`貼り付け`ボタンによる従来の手動入力もそのまま使えます。

ヘッダー領域は、語句ではなく「人物である証拠」で判定します。メールアドレス・`氏名 (Surname,I.)`形式・プロフィールカードを開く要素のいずれかを持たない文字列は候補にしません。`アプリ`や`リアクション`のような画面上部のコマンドは、`role="banner"`・`role="toolbar"`などのランドマーク内にあるため走査対象から除外します。

Outlookの画面構造が変わって検出できない場合は、これまでどおりOutlookの差出人名をコピーし、`貼り付け`ボタンを押してください。そのときは`閲覧ウィンドウを特定できません`のように原因を表示します。

### 差出人が検出できないときの調査

`tools/inspect-sender.js`は、Outlookの実際のDOM構造を調べるための調査用スクリプトです（拡張機能の一部ではありません）。

1. Outlook でメールを開き、`F12`で DevTools を開いて`コンソール`タブを選びます。
2. 貼り付けが禁止されている場合は、コンソールに`allow pasting`と入力して Enter を押します。
3. `tools/inspect-sender.js`を開き、先頭の`const SENDER = "";`に画面上の差出人名をそのまま入れます。
4. ファイル全体をコンソールへ貼り付けて Enter を押します。結果はクリップボードにコピーされます。

出力はタグ名・属性・座標などの構造だけで、氏名・メールアドレス・件名・本文は`<SENDER>`や`***`に置き換わります。この結果があれば、その環境のOutlookに合わせてセレクタを調整できます。

差出人の検出はDOMを読むだけなので、`chrome.scripting`で実行します。PDF作成に使うデバッガーAPIには接続しないため、拡張機能を開いただけでは「デバッガーが接続しました」の通知は出ません。

入力例には実在の利用者を特定しない`山田 太郎 (Yamada,T.)`を使用しています。

アドレスバーが`https://outlook.office.com/mail/`のままでも、選択中のメール行からItem IDを取得します。`outlook.office.com/mail/inbox/id/...`形式は直接埋め込まず、`https://outlook.cloud.microsoft/mail/deeplink/read/...?...&exvsurl=1`形式へ変換してPDFへ埋め込みます。個別URLを特定できない場合、メールトップへのリンクで代用せずエラーを表示します。

## トラブルシューティング

- `Could not establish connection` や `Cannot access a chrome-extension:// URL of different extension` が表示されていた問題は修正済みです。最新版ではコンテンツスクリプトを注入せず、PDF 出力にも使用する Edge のデバッグ API 経由で印刷用ページを準備します。
- Outlook のサインイン画面やメール一覧だけを表示している場合は保存できません。対象メールを開いてから実行してください。
- Outlookの画面に閲覧ペインを識別する属性がない場合も、ページ全体を探索してメール情報を取得します。
- エラーの先頭に `【失敗箇所: ...】` を表示します。`Edge のPDF機能への接続` ならURL取得・PDF作成より前のセキュリティ制限、`メール内容とURLの取得` ならOutlook画面の読み取り、`PDFの作成` ならPDF変換段階の問題です。
- `Cannot access a chrome-extension:// URL of different extension` をEdgeが返した場合は、標準の印刷画面へ自動的に切り替えます。そこで **PDFとして保存** を選択すれば、元メールリンク付きの内容と推奨ファイル名を維持して保存できます。
